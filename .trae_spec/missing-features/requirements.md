# 闲置物品校园交易平台缺失功能实现需求文档

## 介绍

闲置物品校园交易平台经过技术诊断，发现以下核心功能缺失或未完整实现。本需求文档将指导这些功能的设计与实现，完善系统功能闭环。

**当前问题**：
- 消息通知系统仅有数据库表结构，业务逻辑完全未实现
- 纠纷处理系统仅有Entity和Repository，Service/Controller/前端缺失
- 密码重置功能仅有占位链接，无实际实现
- 聊天功能后端完整但前端缺失，用户无法使用
- 订单缺少自动确认收货的定时任务
- WebSocket仅用于聊天，无通用通知推送机制

**修复目标**：
- 实现完整的消息通知系统
- 实现纠纷处理流程
- 实现密码重置功能
- 实现聊天页面
- 添加自动确认收货定时任务
- 完善WebSocket通知推送

## 术语表

- **通知(Notice)**: 系统向用户发送的消息，包括订单状态变更、系统公告等
- **纠纷(Dispute)**: 交易双方对订单产生争议时发起的申诉流程
- **密码重置(Password Reset)**: 用户忘记密码时通过邮箱/手机验证码重置密码的流程
- **即时通讯(Instant Messaging)**: 买卖双方通过WebSocket实时聊天的功能
- **自动确认收货**: 订单发货后超过N天系统自动确认收货的定时任务

## 需求

### 需求 1: 消息通知系统

**用户故事:** 作为用户，我希望接收系统通知，以便及时了解订单状态变更和系统公告

#### 验收标准
1. WHEN 订单状态变更 THEN 系统SHALL 向相关用户发送通知
2. WHEN 用户查看通知列表 THEN 系统SHALL 显示未读通知数量和通知详情
3. WHEN 用户点击通知 THEN 系统SHALL 标记为已读并跳转到相关页面
4. WHEN 管理员发布公告 THEN 系统SHALL 向所有用户推送通知
5. WHEN 用户登出/登入 THEN 系统SHALL 正确显示未读通知数量

### 需求 2: 纠纷处理系统

**用户故事:** 作为买家/卖家，当交易出现争议时，我希望可以发起纠纷，以便获得平台介入处理

#### 验收标准
1. WHEN 买家/卖家发起纠纷 THEN 系统SHALL 创建纠纷记录并通知对方
2. WHEN 被申请人收到纠纷 THEN 系统SHALL 发送通知并允许其回复
3. WHEN 管理员审核纠纷 THEN 系统SHALL 更新纠纷状态并通知双方
4. WHEN 纠纷处理完成 THEN 系统SHALL 记录处理结果并更新订单状态
5. WHEN 查看纠纷列表 THEN 系统SHALL 按状态分类显示纠纷

### 需求 3: 密码重置功能

**用户故事:** 作为用户，当我忘记密码时，我希望可以通过邮箱验证码重置密码，以便恢复账户访问

#### 验收标准
1. WHEN 用户点击忘记密码 THEN 系统SHALL 显示密码重置页面
2. WHEN 用户输入注册邮箱 THEN 系统SHALL 发送6位验证码到邮箱
3. WHEN 用户输入正确验证码 THEN 系统SHALL 允许设置新密码
4. WHEN 密码重置成功 THEN 系统SHALL 提示用户重新登录
5. WHEN 验证码过期 THEN 系统SHALL 提示验证码已失效

### 需求 4: 聊天页面

**用户故事:** 作为买家，我希望可以与卖家实时聊天，以便沟通交易细节

#### 验收标准
1. WHEN 用户点击联系卖家 THEN 系统SHALL 打开/创建聊天会话
2. WHEN 用户发送消息 THEN 系统SHALL 通过WebSocket实时推送给对方
3. WHEN 用户接收消息 THEN 系统SHALL 实时显示新消息并播放提示音
4. WHEN 查看聊天列表 THEN 系统SHALL 显示最近会话和最后一条消息
5. WHEN 用户有未读消息 THEN 系统SHALL 在导航栏显示未读数量

### 需求 5: 自动确认收货

**用户故事:** 作为卖家，当买家长时间不确认收货时，我希望系统能自动确认，以便完成交易

#### 验收标准
1. WHEN 订单发货超过7天 THEN 系统SHALL 自动确认收货
2. WHEN 自动确认收货 THEN 系统SHALL 更新订单状态为已完成
3. WHEN 自动确认收货 THEN 系统SHALL 向买卖双方发送通知
4. WHEN 定时任务执行 THEN 系统SHALL 记录执行日志

### 需求 6: WebSocket通知推送

**用户故事:** 作为用户，我希望实时收到通知推送，以便及时响应重要事件

#### 验收标准
1. WHEN 用户在线 THEN 系统SHALL 通过WebSocket推送通知
2. WHEN 用户离线 THEN 系统SHALL 保存通知到数据库
3. WHEN 用户重新上线 THEN 系统SHALL 推送未读通知
4. WHEN 通知被读取 THEN 系统SHALL 同步更新已读状态
