# 闲置物品校园交易平台 - 项目规则

## 项目概述

**愿景：** 建立安全高效的校园闲置交易平台，促进资源循环，培养学生环保与经济意识。

**标语：** "闲置不闲，变废为宝，绿色校园，你我共创"

**目标：**
| 阶段 | 功能 |
|------|------|
| 短期 | 基础交易、物品发布、身份认证 |
| 中期 | 订单管理、评价系统、聊天功能 |
| 长期 | AI赋能、移动端、校园合作 |

**核心用户：** 在校学生、毕业生、学校行政人员、访客（功能受限）

---

## 技术栈

### 前端
- Vue 3.5+ / Vite 8.0+ / Pinia 3.0+ / Element Plus 2.13+ / Axios 1.15+

### 后端
- Spring Boot 3.2+ / Java 17+ / MySQL 8.0+ / Redis / JWT

### 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 前端类名 | 帕斯卡 | `UserProfile` |
| 前端常量 | 蛇形 | `MAX_FILE_SIZE` |
| 后端类名 | 帕斯卡 | `UserController` |
| 后端方法名 | 驼峰 | `getUserById` |
| 数据库字段 | 蛇形 | `created_at` |
| 数据库表名 | 复数蛇形 | `users`, `idle_items` |

---

## 数据库规范

- 表名使用复数蛇形：`users`, `idle_items`, `categories`
- 主键、外键必须建立索引
- API遵循RESTful风格
- 统一响应格式：
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2024-01-01T00:00:00Z"
}
```

---

## 安全规范

### JWT 配置
- 密钥从环境变量读取（禁止硬编码）
- access-token 有效期：1小时

### 权限分级
| 角色 | 权限 |
|------|------|
| 访客 | 浏览、搜索（受限） |
| 学生 | 完整交易功能 |
| 管理员 | 内容审核、用户管理 |
| 超级管理员 | 系统配置 |

### 数据保护
- 密码使用 BCrypt 加密
- 敏感字段必须脱敏

### 文件上传
- 允许类型：`jpg`, `png`, `webp`
- 大小限制：5MB

## 开发规范

### 代码审查要求（强制执行）

在完成任何代码修改后，必须对所修改的代码进行全面的逻辑性审查和问题排查。确保通过审查确认代码修改达到预期功能且不存在明显问题后方可提交或合并。

#### 审查内容清单：
- [ ] **代码逻辑的完整性与正确性**
  - 验证核心业务逻辑是否符合预期
  - 检查条件判断、循环控制的逻辑正确性
  - 确认数据流转路径正确无误

- [ ] **边界条件的处理**
  - 空值（null/undefined）处理是否正确
  - 极值（最大值、最小值）处理是否完善
  - 边界索引（数组越界、字符串截取）检查
  - 异常输入的容错处理

- [ ] **潜在的错误与漏洞**
  - 安全风险（注入、XSS、越权等）
  - 数据一致性问题（并发、事务等）
  - 资源泄漏（文件、连接、内存等）
  - 逻辑漏洞（竞态条件、死锁等）

- [ ] **与其他模块的兼容性**
  - API 接口兼容性检查
  - 数据格式一致性验证
  - 依赖模块变更影响评估
  - 向后兼容性验证

- [ ] **性能影响评估**
  - 数据库查询优化分析（N+1问题、索引等）
  - 网络请求优化评估
  - 算法复杂度分析
  - 缓存策略评估

- [ ] **是否符合项目的编码规范**
  - 命名规范检查
  - 代码风格一致性
  - 注释完整性（仅复杂逻辑需要）
  - 文件组织和代码结构

#### 审查确认标准：
- 所有已识别的问题已修复
- 代码可通过编译且无错误
- 相关测试用例通过
- 代码变更范围最小化（仅修改必需部分）

### 测试覆盖率
- 单元测试覆盖率 ≥ 80%
- 集成测试覆盖核心流程
- E2E测试覆盖关键用户路径

### 代码评审检查项
- [ ] 功能正确性
- [ ] 安全（防注入、XSS等）
- [ ] 性能考虑
- [ ] 代码质量

### API 端点
- 所有 API 端点必须有对应测试
- 遵循 `src/utils/errors.ts` 中现有的错误处理模式

### TypeScript
- 使用严格模式
