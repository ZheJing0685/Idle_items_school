# 导航栏重写规范

## Why

当前导航栏功能单一，仅包含首页和浏览物品两个导航项，无法满足系统多角色、多功能的导航需求。随着系统功能扩展（发布、订单、收藏、消息、管理后台等），需要根据用户角色（游客、普通用户、管理员）提供差异化导航体验，提升用户操作效率和系统可用性。

## What Changes

- [ ] 重构导航栏组件结构，支持基于角色的动态导航项
- [ ] 实现三种角色导航模式：游客、普通用户、管理员
- [ ] 优化导航项布局，将常用功能置于一级导航
- [ ] 改进移动端适配，确保响应式体验
- [ ] 保持现有设计系统的一致性

## Impact

- **Systems:** 前端导航系统、用户认证系统、路由系统
- **Files:** 
  - `src/components/Header.vue` - 主要修改文件
  - `src/styles/components/header.css` - 样式调整
  - `src/store/index.js` - 可能需要扩展用户状态
- **Users:** 
  - 游客：看到基础导航（首页、浏览、登录/注册）
  - 普通用户：看到完整用户功能导航
  - 管理员：看到管理后台入口

## ADDED Requirements

### 角色感知导航

**Scenario:** 用户访问网站时，系统根据登录状态和角色显示不同导航项

**Acceptance Criteria:**
- [ ] 游客模式显示：首页、浏览好物、登录、注册
- [ ] 普通用户模式显示：首页、浏览好物、发布、个人中心（含下拉菜单）
- [ ] 管理员模式显示：普通用户所有功能 + 管理后台入口
- [ ] 导航项数量不超过7个（不含用户菜单）
- [ ] 当前页面在导航中有明确的激活状态

### 导航项优先级

**Scenario:** 不同角色看到的导航项按使用频率排序

**Acceptance Criteria:**
- [ ] 游客：首页 > 浏览好物 > 登录 > 注册
- [ ] 普通用户：首页 > 浏览好物 > 发布 > 用户菜单
- [ ] 管理员：首页 > 浏览好物 > 发布 > 管理后台 > 用户菜单

### 移动端适配

**Scenario:** 在移动设备上导航栏需要良好展示

**Acceptance Criteria:**
- [ ] 移动端导航项文字可隐藏，仅显示图标
- [ ] 用户菜单在移动端保持可用
- [ ] 搜索框在移动端可折叠或简化
- [ ] 触摸目标尺寸不小于44×44px

## MODIFIED Requirements

### 导航栏布局

**Before:** 固定显示首页和浏览好物两个导航项

**After:** 根据角色动态显示不同导航项，保持布局一致性

**Scenario:** 用户在不同页面间导航

**Acceptance Criteria:**
- [ ] 导航栏高度保持一致（桌面端72px，移动端56px）
- [ ] 导航项间距符合设计系统（8px倍数）
- [ ] 激活状态使用主色调高亮

### 用户菜单

**Before:** 简单的下拉菜单，功能较少

**After:** 完整的用户功能入口，包含所有个人相关功能

**Scenario:** 登录用户点击用户头像或名称

**Acceptance Criteria:**
- [ ] 菜单包含：个人中心、我的发布、我的订单、我的收藏、消息中心、消息通知
- [ ] 管理员额外显示：管理后台入口
- [ ] 菜单项有清晰的图标和文字标签
- [ ] 退出登录功能正常工作

## REMOVED Requirements

### 静态导航项

**Reason:** 当前静态导航无法满足多角色需求，需要动态生成

**Migration:** 导航项将根据用户角色动态生成，无需手动维护
