# 项目概览与架构

## 1. 项目简介

| 项目 | 说明 |
|------|------|
| 项目名称 | 闲置物品校园交易平台 |
| 愿景 | 建立安全高效的校园闲置交易平台，促进资源循环，培养学生环保与经济意识 |
| 标语 | "闲置不闲，变废为宝，绿色校园，你我共创" |

### 目标用户

| 角色 | 说明 |
|------|------|
| 在校学生 | 核心用户，发布和购买闲置物品 |
| 毕业生 | 毕业季批量出售闲置物品 |
| 学校行政人员 | 管理员，审核内容、管理用户 |
| 访客 | 功能受限，仅可浏览 |

### 分阶段目标

| 阶段 | 功能 |
|------|------|
| 短期 | 基础交易、物品发布、身份认证 |
| 中期 | 订单管理、评价系统、聊天功能 |
| 长期 | AI 赋能、移动端、校园合作 |

## 5. 核心业务流程

### 5.1 用户注册/登录

```
用户 → 填写注册信息 → 后端校验唯一性 → BCrypt 加密密码 → 写入数据库 → 返回成功
用户 → 输入用户名/密码 → 后端验证凭据 → 生成 JWT Token → 返回 Token + 用户信息
```

### 5.2 物品发布/浏览

```
卖家 → 填写物品信息 + 上传图片 → 后端压缩/加水印 → 状态设为 PENDING → 管理员审核 → 状态变为 ACTIVE
买家 → 浏览物品列表 → 按分类/价格/成色筛选 → 查看详情 → 收藏/联系卖家
```

### 5.3 下单/支付/发货/收货

```
买家 → 创建订单 → 状态: PENDING_PAYMENT
买家 → 支付订单 → 状态: PAID
卖家 → 确认发货 → 状态: SHIPPED
买家 → 确认收货 → 状态: COMPLETED
（超时 30 分钟未支付 → 自动取消 → CANCELLED）
（买家可申请退款 → REFUND_REQUESTED → 管理员处理 → REFUNDED）
```

### 5.4 评价

```
买家 → 订单完成后 → 提交评价（评分 1-5 + 文字 + 图片）→ 评价入库 → 更新卖家信用分
```

### 5.5 管理员审核

```
管理员 → 审核待上架物品 → 通过/拒绝
管理员 → 审核实名认证 → 通过/拒绝
管理员 → 处理退款申请 → 批准/拒绝
管理员 → 管理用户状态 → 启用/禁用/封禁
```

## 6. 分层架构说明

### 前端分层

```
Views (页面) → Components (组件) → Store (Pinia 状态) → API Services (接口) → Axios (HTTP) → 后端
```

| 层 | 职责 |
|----|------|
| Views | 页面级组件，组合 Components 和 Store |
| Components | 可复用的 UI 组件 |
| Store (Pinia) | 全局状态管理（用户、物品、购物车） |
| API Services | 封装后端 API 调用，含缓存和请求合并 |
| Axios | HTTP 客户端，统一拦截器处理认证和错误 |

### 后端分层

```
Controller (控制器) → Service (业务逻辑) → Repository (数据访问) → MySQL
```

| 层 | 职责 |
|----|------|
| Controller | 接收请求、参数校验、调用 Service、返回响应 |
| Service | 业务逻辑处理、事务管理 |
| Repository | 数据库操作（JPA 自动实现） |
| Entity | 数据模型，映射数据库表 |

### 横切关注点

| 关注点 | 实现 |
|--------|------|
| 认证授权 | JWT + Spring Security + @RequireRole 注解 |
| 缓存 | Redis（物品详情 30 分钟、分类树 1 小时、热门物品 10 分钟） |
| 实时通信 | WebSocket（聊天功能） |
| 定时任务 | OrderTimeoutTask（每 5 分钟检查超时订单） |
| 安全防护 | XSS 过滤器 + Redis 滑动窗口限流（60 次/分钟） |
| 异常处理 | GlobalExceptionHandler 统一异常处理 |

### 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1234567890123
}
```
